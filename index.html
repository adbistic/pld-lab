Bits & basic circuits

A digital circuit only knows two things: 1 (high voltage, ON) and 0 (low voltage, OFF). Everything else is built from that.

A switch and a LED

The simplest circuit: a switch drives a wire, the wire drives a LED. Switch up → wire is 1 → LED lights. On the FPGA board the switches are called SW0…SW15 and the LEDs LED0…LED15.

Binary numbers

Many bits side by side make a number. Each position is worth double the one on its right: 8 4 2 1. So 1010 = 8 + 2 = 10. Click the bits:

Hex (base 16) is a short way to write 4 bits: 0–9 then A=10 … F=15. So 1010 = A.

Four values in Verilog

ValueMeaning
0logic low / false
1logic high / true
xunknown (simulator does not know yet)
zhigh-impedance: wire is disconnected
Writing numbers4'b1010 = size 4 bits, base binary, value 1010. 8'hFF = 8 bits hex FF. 4'd9 = decimal 9. No size → 32 bits.

Active-low

Sometimes a signal does its job when it is 0. That is called active-low. The 7-segment display on the Nexys4 DDR is active-low: a segment lights when you send 0. Remember this — it shows up in labs 3, 4 and 8.

Number systems binary, hex, signed

Hardware only stores bits. Decimal, hex, signed, BCD are just different ways for humans to read the same bits.

Positional numbers

In decimal, 472 = 4×100 + 7×10 + 2×1. Each place is worth 10× the one to its right. Binary works the same with 2×: places are worth …16, 8, 4, 2, 1.

ConvertHowExample
binary → decimaladd the place values of the 1s10110 = 16+4+2 = 22
decimal → binarydivide by 2 again and again, read the remainders bottom-up13: 13/2=6 r1, 6/2=3 r0, 3/2=1 r1, 1/2=0 r1 → 1101
binary → hexcut into groups of 4 from the right, one hex digit per group1011 0110 = B6
hex → binaryeach hex digit becomes 4 bits3C = 0011 1100

How big? n bits hold 2n different values: 0 … 2n−1. So 4 bits → 0…15, 8 bits → 0…255. To store the value N you need enough bits that 2n > N. (5,000,000 needs 23 bits — lab 8.)

Negative numbers: two's complement

The leftmost bit gets a negative weight. In 4 bits the weights are −8, 4, 2, 1. So 1011 = −8 + 2 + 1 = −5. Range of n bits: −2n−1 … 2n−1−1 (4 bits: −8 … 7).

To negate a number: flip all bits, then add 1. 5 = 0101 → 1010 → 1011 = −5.

Why it is cleverThe same adder works for signed and unsigned numbers. Subtraction is just addition: a − b = a + (~b) + 1. That is how an adder-subtractor is built.

Overflow: the result does not fit. Unsigned: there is a carry out. Signed: two positives give a negative (or two negatives give a positive). In Verilog, numbers are unsigned unless you write signed.

Codes are not numbers

BCD stores each decimal digit in its own 4 bits: 25 = 0010 0101 (binary 25 would be 11001). Gray code changes only one bit between neighbours. One-hot has exactly one 1. These are covered in lab 4.

Logic gates

A gate is a tiny machine: bits go in, one bit comes out, following a fixed rule. Pick a gate and flip the inputs.

1 only if all inputs are 1. "Both."
OR a | b
1 if any input is 1. "At least one."
NOT ~a
Flips the bit.
XOR a ^ b
1 if inputs are different. Great for adders and parity.
NAND / NOR ~(a&b)
AND / OR followed by NOT.
XNOR ~(a^b)

Gates in Verilog (gate-level)

From truth table to simple equation

Any truth table can be turned into gates. First get an equation that works, then make it smaller.

Step 1 · Sum of products (SOP)

Each row of a truth table where the output is 1 is called a minterm: an AND of all inputs (with NOT on the ones that are 0). OR all minterms together and you have a correct equation — always.

abfminterm
000
011~a & b
100
111a & b

f = (~a & b) | (a & b). Correct, but look: b is 1 in both terms and a does not matter. So f = b. That is simplification.

Step 2 · Simplify with algebra

The one rule that does most of the work: (X & y) | (X & ~y) = X. Two terms that differ in only one variable merge, and that variable disappears.

Step 3 · Karnaugh map (K-map) — the same rule, as a picture

  1. Draw the truth table as a grid. Columns are ordered 00, 01, 11, 10 (Gray order), so neighbours differ in one bit.
  2. Write the 1s in the grid.
  3. Circle groups of 1s. Group sizes must be 1, 2, 4 or 8. Make every group as big as possible. The map wraps around the edges.
  4. Use as few groups as possible, until every 1 is covered. Groups may overlap.
  5. Each group = one AND term: keep only the variables that stay the same inside the group.

Click cells to toggle them and watch the simplest equation:

Don't caresIf an input combination can never happen (like BCD codes 10–15), you may treat its cell as 0 or 1, whichever makes bigger groups. In lab 3 we chose to blank the display instead, so those cells were fixed to 1 (segment off).

Do I need this in Verilog?

Vivado simplifies for you: you can write a case with the whole truth table. But dataflow exercises ("derive the expressions on paper") and exams ask for it, and it helps you understand what the tools build.

POS (product of sums) is the mirror image: look at the 0 rows, OR the inputs (inverted when they are 1), AND everything.

Combinational logic

Output depends only on the inputs right now. No memory, no clock. Change an input → output changes (after a tiny delay). Gates glued together.

Multiplexer (MUX) — a selector switch

Two data inputs x, y and a select s. If s=0 the output copies x, if s=1 it copies y. Equation: m = (~s & x) | (s & y).

Decoder — "which one?"

n input bits → 2n outputs, exactly one is 1. A 3-to-8 decoder turns the number 5 into "light LED5". Used to pick memory words.

Encoder — the reverse

Many inputs → the number of the active one. A priority encoder picks the most important input if several are active.

7-segment display

Seven LEDs named a–g form a digit. A BCD to 7-segment decoder turns 4 bits (0–9) into 7 segment signals. On our board: 0 = segment ON.

Adder

Adding two bits: sum = a ^ b, carry = a & b. In Verilog just write {cout, sum} = a + b; — the tools build the gates for you.

Golden ruleIn combinational code every output must get a value in every case. If you forget one, the tool adds a latch (unwanted memory). Fix: give default values first, or always use else and default.

1 · Multiplexer (MUX)

Think of a railway switch. The select lines are a binary number that says which data input reaches the output. n select bits choose between 2n inputs: 1 select → 2-to-1, 2 selects → 4-to-1, 3 selects → 8-to-1.

Equation of a 4-to-1: each data input is ANDed with "its" select code, then all are ORed:
m = (~s1&~s0&d0) | (~s1&s0&d1) | (s1&~s0&d2) | (s1&s0&d3)

Good to knowBig muxes are built from small ones (lab 2 ex. 6). Every if/else and case you write becomes muxes in hardware. A mux with constants on its data inputs can make any truth table — that is what a LUT is.

2 · Decoder

Input: an n-bit number. Output: 2n lines, only the line with that number is active. Each output is simply the AND of the inputs for one row of the truth table (a minterm).

  • Enable input: when disabled, no output is active. Lets you combine chips: two 3-to-8 decoders + the 4th bit on the enables = one 4-to-16 decoder.
  • Active-low outputs (74138): the chosen line is 0, the others are 1.
  • Uses: choose a memory word, choose which 7-seg digit is on, turn a state number into control signals.
  • Any logic function = decoder + OR of the rows where the function is 1.

A 7-segment decoder is a different kind of decoder: 4 bits in, 7 bits out, and several outputs can be active together. It is a code converter (BCD code → segment code).

3 · Encoder & priority encoder

The reverse of a decoder: 2n lines in, n-bit number out. A plain encoder only works if exactly one input is active. A priority encoder solves "what if two are active?" — the highest-numbered one wins. It also adds a valid output (GS in lab 3) that says "at least one input is active".

In Verilog, priority = an if / else if chain: the first true line wins. Use: interrupt requests, finding the first 1 in a word.

4 · Comparator

Start with 1 bit:

OutputEquationWhy
eq~(a ^ b) (XNOR)equal when not different
gt (a > b)a & ~bonly 1 > 0
lt (a < b)~a & bonly 0 < 1

For more bits, compare like you compare decimal numbers: start at the most significant bit. If it differs, you are done. If it is equal, look at the next bit. For 2 bits:
eq = eq1 & eq0   gt = gt1 | (eq1 & gt0)   lt = ~(eq | gt)

Lab 4 uses a comparator against a constant (v > 9). Lab 5 builds one with a ROM instead of gates.

5 · Adders

Half adder: adds 2 bits. sum = a ^ b, carry = a & b.
Full adder: adds 2 bits plus a carry-in, so adders can be chained.

sum = a ^ b ^ cin   cout = (a & b) | (cin & (a ^ b))
Chain 4 full adders (carry out → next carry in) = a 4-bit ripple-carry adder. Adding two n-bit numbers gives n+1 bits. That is why lab 6 ex. 3 needs a 5-bit sum and the lab 10 multiplier needs a carry bit.

More combinational parts

The remaining blocks you meet in real designs and in a CPU.

Demultiplexer (DEMUX)

The mirror of a mux: one data input, n select bits, 2n outputs. The data goes to the selected output, the others are 0. It is a decoder whose outputs are ANDed with the data.

Tri-state buffer & shared bus

A normal output is always 0 or 1. A tri-state output has a third option: z = let go of the wire. That lets several devices share one wire (a bus), as long as only one drives at a time. If two drive different values, you get a conflict (x).

Inside an FPGATri-states only exist at the pins. Inside the chip, use a mux to choose who "talks".

Adder-subtractor

One adder does both. To subtract, flip every bit of b (XOR with the sub signal) and feed sub into the carry-in — that is exactly "invert and add 1" from two's complement.

ALU — arithmetic logic unit

The calculator inside every processor: two numbers in, an opcode chooses the operation, one result out, plus flags (zero, carry). Inside: all operations are computed side by side and a mux picks one.

Shifter

Shift left by 1 = ×2. Shift right by 1 = ÷2. A barrel shifter shifts by any amount in one step (it is a bank of muxes). >> fills with 0; >>> on a signed value copies the sign bit. Rotate = bits that fall off come back on the other side: {a[2:0], a[3]}.

Parity generator / checker

XOR of all bits (^data). The sender adds the parity bit; the receiver XORs everything again — if the result is not 0, one bit flipped on the way. Lab 6 ex. 2.

Code converters

Any "code A → code B" block is just a truth table: BCD → 7-segment, BCD → 2-out-of-5, binary → BCD. Binary → true Gray code has a neat formula: g = b ^ (b >> 1).

Sequential logic

Output depends on inputs AND on the past. The circuit has memory. Memory updates on the tick of a clock.

The clock

A clock is a signal that goes 0,1,0,1 forever. The moment it goes 0→1 is the rising edge (posedge). The Nexys4 DDR clock is 100 MHz = 100 million edges per second (pin E3).

D flip-flop = 1 bit of memory

On each rising edge it copies D into Q. Between edges Q holds still, whatever D does. Toggle D, then press Tick or let the clock run.

Register & counter

Many flip-flops side by side = a register. Add 1 every clock = a counter. Counters make slow signals from a fast clock (a clock divider): count to 50,000,000 at 100 MHz and you have half a second.

Finite State Machine (FSM)

A machine that is always in one state and jumps to the next state on the clock edge, based on its inputs. Three parts:

  1. Next-state logic (combinational): where do I go next?
  2. State register (flip-flops): where am I now?
  3. Output logic (combinational): what do I show?

outputs depend on state onlyoutputs depend on state + input
written inside the state circlewritten on the arrow: in/out

Blocking vs non-blocking

= (blocking) runs line by line like normal code. Use it in combinational always @(*).
<= (non-blocking) — all right sides are read first, then all updated together, like real flip-flops. Use it in always @(posedge clk).

Sequential building blocks

Everything with memory is made from flip-flops. These are the standard arrangements, with the Verilog for each.

In Verilog you only write D flip-flops; T and JK behaviour is just logic in front of D: q <= q ^ t;

Register with enable / load

A row of flip-flops that keeps its value until you say "load".

Latch rule reminderA missing else makes a latch only in combinational blocks. In a clocked block, "not assigned" simply means "hold" — that is correct and normal.

Shift register

Flip-flops in a chain: on each clock every bit moves one place and a new bit enters. Uses: serial → parallel (receive data one bit at a time), parallel → serial, delays, the lab 10 multiplier, remembering the last N input bits.

Counters

A register plus an adder. Options: up or down, enable, and a limit (modulo-N: count 0…N−1 then wrap). A mod-10 counter is a BCD / decade counter.

Tick generator (the right way to slow things down)

Instead of making a slow clock, make a pulse that is 1 for a single clock cycle every so often, and use it as an enable.

Edge detector

Turns "button went from 0 to 1" into a one-cycle pulse. Remember the previous value and compare.

Debouncer

A mechanical button bounces: it flickers 0/1 for a few milliseconds when pressed. Fix: accept the new value only after it stayed the same for a while (~10 ms).

PWM — fake analog with one pin

Switch a pin on and off very fast. The fraction of time it is on (duty cycle) sets LED brightness or motor speed. Built from a counter and a comparator.

RAM (memory you can write)

Like the ROM of lab 5, plus a write port: on the clock edge, if we is 1, store din at addr.

A FIFO (queue) is a RAM plus two counters: one says where to write next, one where to read next.

Synchronous vs asynchronous

Synchronous = things change only on the clock edge, all together. Asynchronous = things change whenever an input changes, without waiting for the clock.

The idea

SynchronousAsynchronous
When does it change?only at the clock edgeimmediately, any time
Like…an orchestra following a conductoreveryone playing when they feel like it
Timingeasy to predict and checkglitches and races are possible
In FPGAsthe normal way: one clock for everythingonly for special cases (reset, inputs from outside)

Why does synchronous win? Gates need a little time, and signals arrive at slightly different moments, so wires can show wrong values for a few nanoseconds (glitches). A flip-flop only looks at its input on the clock edge. If the clock is slow enough for all wires to settle, the glitches are never seen.

Synchronous vs asynchronous (ripple) counters

Ripple counter: only the first flip-flop gets the clock. Each next flip-flop is clocked by the output of the one before. The change "ripples" through, so bits update one after another and wrong values appear for a moment.
Synchronous counter: every flip-flop gets the same clock, all bits change together. This is what count <= count + 1 builds, and what you should always write.

About the lab clock dividersUsing a counter bit as a clock for other logic (clk_305, clk_1hz) is a small piece of asynchronous design. It is fine for slow lab signals. In real projects you keep one clock and use a one-cycle enable pulse instead: if (tick) state <= next;

Asynchronous inputs: setup, hold, metastability

A flip-flop needs its input to be steady a short time before the clock edge (setup time) and after it (hold time). A switch or button pressed by a human does not care about your clock — it is asynchronous. If it changes exactly at the edge, the flip-flop can hesitate between 0 and 1 for a while (metastability).

The fix is a synchronizer: pass the signal through two flip-flops first.

Synchronous design rules (remember these 4)

  1. One clock for all flip-flops whenever possible.
  2. Memory only in always @(posedge clk) with <=.
  3. Everything else is combinational: assign or always @(*) with =.
  4. Signals from the outside world go through a synchronizer.

Timing & designing an FSM

How fast can a circuit run, and how do you get from a sentence to a working state machine?

Why there is a speed limit

Every gate needs a little time (propagation delay). Between two flip-flops, the signal must leave the first flip-flop, pass through all the gates, and arrive early enough before the next clock edge.

Tclock ≥ tclk→Q + tlogic + tsetup

The slowest path in the whole design is the critical path. It decides the maximum clock frequency: fmax = 1 / Tmin. Move the sliders:

  • Setup time: data must be steady before the edge. Violated when the logic is too slow → lower the clock or shorten the path.
  • Hold time: data must stay steady a moment after the edge.
  • Pipelining: cut a long path in two by adding a register in the middle. Each half is shorter → higher fmax, result arrives one clock later.
  • Vivado checks all of this after implementation: look for WNS (worst negative slack) ≥ 0 in the timing summary.

FSM design in 7 steps

  1. Understand inputs, outputs, and what must be remembered.
  2. States: one for each different "situation". Give them names that say what happened so far.
  3. Diagram: from every state, draw one arrow for every input value. No arrow may be missing.
  4. Moore or Mealy? Moore: output written in the state (changes on the clock, clean). Mealy: output on the arrow (reacts at once, one state fewer).
  5. Encode the states with localparam.
  6. Code the 3 blocks: state register, next-state, output.
  7. Test with an input sequence that visits every arrow.

Typical FSM mistakes

  • No default in the next-state case → latch, or stuck in an unused state.
  • Forgetting reset → state starts as x in simulation.
  • Using = in the state register or <= in the combinational blocks.
  • Output not assigned in some state → latch. Give defaults first.
  • State register too narrow for the number of states (5 states need 3 bits).

What is an FPGA?

A chip full of blank logic blocks and programmable wires. You describe a circuit in Verilog, the tools turn it into a configuration (bitstream), and the chip becomes that circuit.

LUT (look-up table)
A tiny memory. Address = inputs, data = output. Any 6-input function fits. (Lab 5 shows the same idea with ROM.)
Flip-flops
Next to every LUT. Give memory for sequential logic.
Routing
Programmable switches connect the blocks.
Extras
Block RAM, DSP multipliers, clock managers (MMCM/PLL — lab 8).

Write any module from scratch

Never start by typing code. Follow the same 6 steps every time and the code almost writes itself.

The 6-step method

  1. Box. Draw a box. Inputs on the left, outputs on the right, with their widths. This becomes the module line.
  2. Memory? Ask: does the output depend only on the inputs now (combinational), or also on the past (sequential → needs clock and flip-flops)?
  3. Table. Combinational: write the truth table. Sequential: draw the state diagram or say what the registers do on each clock.
  4. Style. Pick what the task asks for (see the table below).
  5. Type it. Skeleton first: module … endmodule, then the logic. wire for assign, reg for always.
  6. Check. Every output assigned in every case? Widths match? Then simulate with a tiny testbench.

How to read a circuit

A big schematic looks scary. Read it the same way every time: left to right, one wire at a time.

Combinational circuit: 5 steps

  1. Find the ends. Mark the inputs (usually left) and outputs (usually right).
  2. Name every internal wire (n1, n2, …). One name per gate output.
  3. Write one small equation per gate, going left to right. A small circle (bubble) means NOT.
  4. Substitute until the output only contains inputs.
  5. Understand it: make a truth table or try a few input values, then ask "which block from the cheat sheet is this?"

Try it. Flip the inputs and follow the values along the wires:

Each named wire becomes a wire, each gate becomes one line. Reading a circuit and writing gate-level Verilog are the same skill:

Shapes to recognise at a glance

You see…It is…
ANDs feeding one OR, with a signal and its NOT going to different ANDsa multiplexer (that signal is the select)
many ANDs, each with a different mix of the same inputs inverted / not inverteda decoder
XOR of two inputs + AND of the same twoa half adder (sum, carry)
XNORs feeding an ANDan equality comparator
a trapezoid with 0 / 1 labelsmux symbol
a box with a small triangle on one pinflip-flop / register; the triangle is the clock
an output wire going back to an inputfeedback = memory or a counter

Sequential circuit: 4 steps

  1. Find the flip-flops / registers (triangle = clock pin). Their outputs Q are the state.
  2. Cut the circuit at the flip-flops. Everything between a Q and the next D is plain combinational logic — read it with the 5 steps above.
  3. For each D ask: "what will be loaded at the next clock edge?" Write it as Q_next = …
  4. Walk through a few clocks in a small table: clock number, state, next state, outputs.

Example — lab 10 multiplier drawing. Flip-flops: the 9-bit product register (ACC + multiplier) with clock CLK. Combinational between Q and D: a 4-bit adder (ACC + multiplicand). Control lines Load / Sh / Ad choose what is loaded: the multiplier, the shifted value, or the adder result. Bit 0 (M) goes back to the controller — that is the feedback that decides "add or not". So: a register that either adds or shifts each clock, told what to do by an FSM. Step through it on the Lab 10 page.

Example — block diagram of an FSM. Inputs + present state → next-state logic → state register → output logic. If the output logic also uses the inputs it is Mealy, otherwise Moore.

Reading a timing diagram (waveform)

  1. Find the clock and mark its rising edges.
  2. Registered signals change just after an edge; combinational ones change right after their inputs.
  3. At each edge, read the inputs just before it — that is what the flip-flops capture.
  4. Red / x in the simulator = never assigned yet: usually a missing reset or undriven input.

Deep dive: the multiplexer and the 3 ways to write it

What a mux is: a switch for signals. s decides which input reaches the output. Equation: m = (~s & x) | (s & y). Read it as two "gates": ~s & x lets x through when s=0, s & y lets y through when s=1, and the OR joins them (only one side is ever active).

StyleYou describeLooks likeLeft side must be
Gate-level (structural)every gate and wireand (w1, x, ns);wire
Dataflowthe equationassign m = s ? y : x;wire
Behavioralwhat should happenalways @(*) if (s) m = y; else m = x;reg

Gate primitives: output comes first: and (out, in1, in2);. No instance name needed. Every wire between two gates must be declared with wire.

Wider mux: a 2-bit mux is two 1-bit muxes that share s. In dataflow nothing changes except the widths — the same s ? y : x works for any width.

Bigger mux from small ones (ex. 6): first mux picks between u and v (using s0); second mux picks between that result and w (using s1). So s1=1 → w, no matter what s0 is.

Delays: assign #3 m = …; means the output changes 3 ns after an input changes. Only simulation uses it; the board ignores it.

Mistakes seen most oftenForgetting reg on an output assigned in always · forgetting the else (creates a latch) · mixing up port order when instantiating — use named ports .x(u).

Deep dive: decoder, 74138, 7-segment, priority encoder

Decoder n-to-2ⁿ: turns a binary number into "one line on". 3 inputs → 8 outputs, output number x is 1. Each output is one AND of all inputs (inverted or not): y[5] = x[2] & ~x[1] & x[0]. Shortcut: assign y = 8'b0000_0001 << x;

74138: the same decoder as a real chip, with two twists: outputs are active-low (the selected one is 0, the rest are 1) and it only works when the enables say so: g1=1, g2a=0, g2b=0. Otherwise all outputs are 1 (nothing selected). Enables let you chain chips into a bigger decoder.

BCD → 7-segment: also a decoder, but the outputs are 7 segments a–g instead of 8 lines. On this board a segment lights when its pin is 0, and a digit is switched on when its anode pin is 0. Build the pattern by asking for each segment "is it on for this digit?".

digitsegments onseg[6:0] = gfedcba

Encoder: the reverse of a decoder (line number → binary). A plain encoder breaks if two inputs are 1. A priority encoder fixes that: the most important input wins (in the lab the inputs are active-low, so the highest 0 wins). In Verilog the priority comes for free from if … else if …: the first true condition wins. Extra outputs tell you "some input was active" and pass the enable on to the next chip.

Deep dive: codes and the "add 6" trick

A code is just a table. BCD, 2-out-of-5, Gray, 7-segment: for every input value you list the output pattern. In Verilog that is a case or one assign per output bit.

2-out-of-5: every digit uses 5 bits with exactly two 1s. Why? If one bit flips on the way, the count of 1s is no longer two → the error is detected.

Binary → two decimal digits (ex. 3), value v = 0…15:

  1. Comparator: z = 1 when v > 9. z is also the tens digit (0 or 1).
  2. Circuit A: computes the ones digit for 10…15, which is v − 10 (10→0, 11→1 … 15→5).
  3. Mux: z = 0 → show v itself; z = 1 → show the circuit A result.
  4. 7-segment decoder shows the chosen digit.

This is how you read any block diagram: find what each block outputs, then follow the select signals.

Sized constants: 4'd9 = 4 bits, decimal 9. 8'hA5 = 8 bits, hex A5 = 1010_0101. No size = 32 bits. Underscores are ignored and only help reading.

Deep dive: a ROM is a truth table you can look up

Idea: instead of working out gates, store the answer for every input combination. The inputs glued together form the address; the stored word is the data.

TermMeaning2-bit comparator example
address widthnumber of input bitsa and b, 2 bits each → 4 bits
depthnumber of words = 2^address bits16 lines in the file
data widthnumber of output bits3 (lt, gt, eq)

How to fill the file: go through the addresses in order 0000, 0001, … For each one, split the address back into a and b, work out the answer by hand, write one line. $readmemh does the same with hex numbers.

Order matters: {a, b} puts a in the top bits. If you write {b, a} the table is read in a different order and the outputs look scrambled.

On the FPGA a small ROM becomes LUTs — a LUT is a tiny ROM. Add the .txt file to the project as a design source so Vivado can find it.

Deep dive: clocks, dividers and the multiplexed display

Why a Clocking Wizard? It uses a special block (MMCM/PLL) that makes a new clean clock from the 100 MHz one. locked goes 1 when the new clock is stable — we show it on an LED (dcm).

Slowing down further = counting. At 5 MHz there are 5,000,000 edges per second. Count 0 … 4,999,999 and you have measured exactly 1 second.

Cheap divider: bit k of a free-running counter toggles at f / 2^(k+1). c[13] at 5 MHz → 5,000,000 / 16,384 ≈ 305 Hz.

Multiplexed 7-segment: all 8 digits share the same 7 segment wires. To show different digits: switch on digit 0 and send its pattern, then digit 1 and its pattern, and repeat fast (~305 Hz). The eye sees both lit. Too slow → flicker. Too fast → ghosting.

IP blocks (wizard, binary counter) are ready-made modules. You configure them in a dialog, then instantiate them like your own module. Copy the port names from the generated instantiation template (.veo file).

Deep dive: how to build any FSM

An FSM = a state register (memory) + next-state logic (where to go) + output logic (what to show).

Traffic light: the states are the light patterns; a counter decides how long to stay. When the counter reaches the limit: go to the next state and restart the counter.

Sequence detector (1011): each state means "how much of the pattern I have seen so far": nothing, 1, 10, 101, 1011. On a wrong bit do not always go back to the start — go to the state that matches the longest useful ending. Example: after 101 comes 0 → the last bits are "10", so go to the "10" state.

Deep dive: ASM chart → Verilog, and shift-add multiplication

ASM chart symbols: rectangle = a state (Moore outputs written inside) · diamond = a decision on an input · oval = a conditional action (Mealy, happens only on that path). One rectangle with everything below it up to the next rectangle = one clock cycle.

Translating: each rectangle → one localparam state. Each diamond → an if inside that state's case branch. Register actions (P <= …) go in the clocked block.

Shift-add = school multiplication in binary. For each bit of the multiplier, starting from the right: if the bit is 1, add the multiplicand to the top half; then shift everything right one place. 3 bits → 3 rounds.

step (5 × 3 = 101 × 011)carry + ACCmultiplier part
start0 000011
bit0 = 1 → add 1010 101011
shift right0 010101
bit0 = 1 → add 1010 111101
shift right0 011110
bit0 = 0 → no add, shift0 001111
result (low 6 bits)001111 = 15 ✓

Why 7 bits? 3 (ACC) + 3 (multiplier) + 1 carry bit, because adding two 3-bit numbers can give 4 bits. The carry is shifted back in on the next step.

Datapath + control: the register P and the adder are the datapath (they do the work). The FSM IDLE → TEST → SHIFT → DONE is the controller (it says when). A small counter tells the controller when 3 rounds are over.
